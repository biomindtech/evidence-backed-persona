# Evidence-Backed Persona

**给长期协作的 Agent 用的一套"侧写纪律"：先攒证据，再下结论，结论必须能溯源。**

大多数 agent 记忆系统解决的是"记不记得"——存事实、做检索、压缩上下文。
这套东西解决的是另一个问题：**你凭什么这么判断一个人。**

它不依赖任何框架，是一份可以塞进 `AGENTS.md`、`CLAUDE.md` 或 skill 目录的方法约定。

---

## 它要解决的具体毛病

Agent 和人协作久了，会自然形成"对用户的印象"。常见的三种坏法：

1. **一次印象直接升格成结论**：他今天有点烦，画像里就多了"情绪不稳定"。
2. **同一个观察重复十遍被当成十个证据**：其实都发生在同一个会话里。
3. **结论只增不减**：判断被证明是错的，但没人删，后来者继续照它执行。

这三条都会让 agent 越用越偏，而且**偏得很自洽**——因为它已经把那句话写进了自己的规则。

---

## 三条纪律

### 一、分层：证据不是结论

| 层 | 装什么 | 谁能进 |
|---|---|---|
| 证据层 | 具体发生过什么 | 任何一次观察 |
| 结论层 | 已成立 / 已驳回的判断 | 需要多个独立观察 |
| 画像层 | 稳定描述（事实、偏好、边界） | 只有"已成立" |

**孤例永远停在证据层**，不进画像。这条是整套机制的核心。

### 二、复现按"独立观察者"计数

同一现象出现两次，是不是模式？**取决于这两次是不是同一个观察者看见的。**

- 两个不同窗口/会话/来源 → 算复现，可以升结论；
- 同一个窗口说两遍 → 仍然是一个。

没有这一条，"复现"会退化成"重复提到"。

### 三、驳回与证伪保留，不静默消失

用户说"不是这样"，卡片不删——**驳回本身是证据**。
判断被后续行为推翻，标 `[已证伪]`，保留原文与推翻它的原因。

删掉的东西不会教训后来者。

## 两种用法，按人挑

三层结构完整，但维护成本高：要有人写卡、有人搬卡、有人判。**一个人的场景往往撑不住。**
所以这里给两条路。

| | 三层（团队 / 多 Agent 版） | 轻量（单人长期协作版） |
|---|---|---|
| 适合 | 多个 Agent 或多个协作者共用一个"人设"，需要互相复核 | 一个 Agent 长期跟着一个人 |
| 证据 | 卡片：现象／触发／影响／对策 | 每天一行：原话 ＋ 我为什么意外 |
| 门槛 | 两个独立观察者 | 两个不同日期 |
| 结论放哪 | `HIM.md` 的表格 | 画像条目的行内标记 |
| 维护成本 | 高 | 低（一行） |

**单人硬上三层，最常见的结局**：卡片越积越多，结论一条也没有。我们实测过一周——10 张卡、0 条结论、60 行规则管 10 张卡。这不是执行不力，是**单位错了**：需求是每月一两条观察，机制却按会话记账。

轻量版全文见 [`LIGHTWEIGHT.md`](LIGHTWEIGHT.md)，不到 100 行。

## 怎么接

**方式 A（skill）**：把 `SKILL.md` 放进你的 skills 目录。

**方式 B（约定文件）**：把 `SKILL.md` 里"三层 + 五字段 + 复现计数"三块抄进 `AGENTS.md` / `CLAUDE.md` 的一节。

**方式 C（轻量）**：直接把 `LIGHTWEIGHT.md` 抄进全局规则，一页纸。

模板在 `templates/`，三份空表，直接抄（服务三层版）。

---

## 它不做什么

- **不存私密**：家事、身体状况、私人关系、未公开的创作，不写进公共区。
- **不替人下判决**：画像是"我们怎么看"，不是"他是什么"。他改规则，不改判断。
- **不追求覆盖**：只写读到过、撞见过的；没读的部分不猜。

---

## 一句总结

**证据堆在下面，结论在上面，画像在各自的房间里——三层之间只走一条路：溯源。**
